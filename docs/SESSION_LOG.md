## 1. السياق

هذا ثالث مشروع في سلسلة مشاريع طلابية تُقيَّم على معايير الدكتور (ملف "متطلبات مشروع فلاتر"):

| المعيار | الدرجة |
|---|---|
| التصميم والغنى (≥5 شاشات غير المصادقة، Widgets متنوعة، صور Assets، Row/Column/Stack، ListView/GridView) | 5 |
| المصادقة (تسجيل/دخول بـ Form/Validation + نسيت كلمة المرور فعّالة) | 3 |
| الاستجابة الديناميكية (StatefulWidget، SnackBar، Dialog) | 4 |
| SQLite CRUD | 5 |
| التنقل مع تمرير بيانات + تنظيم متعدد الملفات + APK قابل للتشغيل | 3 |

المشروعان السابقان: **EduAcademy** (022) و**CarCare** (011). كان مطلوباً أن يختلف كِتابي عنهما في الكود والتصميم، مع الاحتفاظ بنفس **آلية الترخيص عن بُعد** ونفس **مفتاح التوقيع**.

الوصف الأصلي للمشروع: *"تطبيق متجر كتب (محاكاة): تصفح الكتب حسب التصنيفات، البحث، إضافة إلى سلة المشتريات أو المفضلة، استعراض تفاصيل الكتاب"*.

## 3. الخطة التي نُفّذت (بالترتيب)

1. بحث → قرار التنقل والتخطيط.
2. توليد 3+3 تصاميم مفهومية → اختيار A.
3. هيكل المشروع: pubspec، الحزمة، التوقيع (نسخ `release-key.jks` و`key.properties` من 011 = نفس المفتاح)، ملفات SQLite للويب.
4. الطبقات: `app_theme` → `models` → `data/db` + `seed` (24 كتاباً) → `repos` → `state` (Provider) → `security` (AccessControl + OtpEngine) → `ui`.
5. Shell بالتنقل المتداخل، ثم الشاشات: رئيسية، تصنيفات، قائمة/بحث، تفاصيل + مراجعات، سلة + كوبونات، مفضلة، طلبات + تفاصيل الطلب، حسابي/تعديل/كلمة المرور/حول، القفل، المصادقة + OTP.
6. الأصول: 24 غلافاً مولَّداً (Pillow + libraqm + خط Amiri) + أيقونة إطلاق متكيّفة + أيقونات ويب.
7. `flutter analyze` → 0، اختبارات (وحدة + واجهة).
8. بناء ويب + فحص بصري آلي (Playwright) لـ 24 حالة.
9. APK موقّع → نشر → رفع GitHub + tag.
10. **v1.1.0**: الأدوار + لوحة المدير + ترقية قاعدة v1→v2 + 8 اختبارات + فحص Playwright لمسار المدير.
11. التوثيق النهائي + `releases/` + `BUILD_GUIDE.md`.

## 5. قرارات معمارية مهمة (ولماذا)

- **Provider (ChangeNotifier) بأربع حالات منفصلة** (Session/Catalog/Cart/Favorites) بدل خدمة واحدة كما في 011/022 → اختلاف بنيوي واضح وسهولة اختبار.
- **`sealed class AccessDecision`** مع `switch` نمطي للترخيص بدل `enum` → يجبر المترجم على تغطية كل الحالات.
- **OTP أبجدي رقمي `XX-XXX`** (بلا 0/O/1/I) بدل 4 أرقام → مختلف عن المشروعين ومقاوم للالتباس.
- **GitHub Contents API أولاً** ثم raw كاحتياط → تجنّب كاش CDN (كان يؤخر تغييرات الترخيص 5 دقائق في المشاريع السابقة).
- **قاعدة البيانات `version: 2` مع `onUpgrade`** → من ثبّت v1.0.0 يُرقّى بلا فقد بيانات (مُختبَر).
- **حذف التصنيف مرفوض إن كان فيه كتب** → حماية سلامة البيانات بدل حذف متسلسل غير متوقع.
- **الأغلفة المُضافة**: أندرويد = نسخ الملف إلى مجلد التطبيق؛ ويب = base64 داخل SQLite → نفس الكود يعمل على المنصتين.
