## C. التصميم للأمي (أبحاث أكاديمية وصناعية)
المصادر: Microsoft Research "Designing Mobile Interfaces for Novice and Low-Literacy Users" (2011)؛ Islam et al., SAGE Open 2023 (مراجعة منهجية لـ42 دراسة)؛ Google NBU (Next Billion Users) guidelines؛ Radiant Digital NBU article.

| المبدأ | التطبيق في سِجِل |
|---|---|
| الأيقونة الملموسة + النص معاً (الأميّون يفضّلون وجود النص حتى لو لا يقرؤونه — يشعرهم بـ"الجدية") | كل زر: أيقونة كبيرة + كلمة واحدة |
| **ثبات مواقع العناصر** (Permanent Object Positioning) → ذاكرة عضلية | أخذ دائماً يمين/أحمر، دفع دائماً يسار/أخضر، في كل الشاشات |
| **تجنّب التمرير** للمستخدم الجديد | الرئيسية بلا تمرير؛ القوائم الطويلة في شاشات مخصصة فقط |
| الصوت كقناة أساسية | TTS لكل فعل؛ ملاحظات صوتية؛ بحث صوتي |
| الأرقام مفهومة أكثر من الحروف | إدخال بالأوراق النقدية + لوحة أرقام كبيرة |
| الوجوه تُميَّز فوراً | الزبون = صورة كبيرة أولاً |
| التغذية الراجعة متعددة القنوات | نجاح = صوت + أخضر + حركة؛ خطأ = صوت + اهتزاز + أحمر |
| التراجع السهل يقلل الخوف | شريط "تراجع" 8 ثوانٍ بعد كل حفظ |
| انتقالات واضحة بين الشاشات | Slide transitions، لا قفزات |
| الفيديو/الصوت التعليمي أول تشغيل | دليل صوتي تفاعلي 60 ثانية |

### اكتشاف مهم في اختبار PDF
`TableHelper.fromTextArray` مع `textDirection: rtl` **لا يقلب ترتيب الأعمدة** تلقائياً — عمود "الرصيد" ظهر يساراً. **الحل:** عكس ترتيب `headers` و`data` يدوياً عند البناء (أو بناء `Table` مخصص). مسجَّل في `08_ERRORS_AND_LESSONS.md`.

## E. هندسة الدفاتر المالية (Ledger Engineering)
المصادر: Modern Treasury "How to Scale a Ledger" (Parts I–VI)؛ systemdesignsandbox Double-Entry؛ trio.dev Payment Ledger Architecture (2026)؛ Frappe immutable ledger discussion.

الخلاصات المُعتمدة (تفصيلها في `04_LEDGER_RULES.md`):
1. الدفتر **إلحاقي فقط** — التصحيح بقيد عكسي.
2. المبالغ **أعداد صحيحة** بأصغر وحدة.
3. الرصيد **يُحسَب** من الحركات، لا يُخزَّن كمصدر حقيقة.
4. الموازنة **لكل عملة على حدة** — لا خلط.
5. **مفتاح تكرار** (idempotency) لكل حركة.
6. **سجل تدقيق** منفصل: من، ماذا، متى.
7. وقتان: `effective/occurred_at` و`recorded_at`.

## F. المزامنة أوفلاين-أولاً
المصادر: Ditto blog on CRDTs (2025)، Adalo "Event-Driven Sync" (2026)، back4app glossary، مقالات Medium عن فشل LWW.

- **الخطر:** Last-Write-Wins يمسح بيانات عند التعارض.
- **الحل المعتمد:** سجل أحداث إلحاقي لكل جهاز (`events_<device>.jsonl`) على Drive → الدمج بلا تعارض للحركات (لأنها لا تُعدَّل) + مفتاح التكرار يمنع الازدواج. الحقول القابلة للتعديل (اسم الزبون) → الأحدث يفوز **مع حفظ القديم في audit_log**.
